## 6.1 Skill이란?

> **Skill(Agent Skill)**은 지침([SKILL.md](http://SKILL.md)), 참고 문서, 스크립트, 템플릿을 하나의 폴더로 묶은 것으로, Claude가 관련 작업을 만났을 때 **스스로 불러와 사용하는** 전문 기술 모듈입니다.

비유하자면, 프롬프트가 "오늘 할 일에 대한 지시"라면 Skill은 **"회사의 업무 매뉴얼 바인더"**입니다. Claude는 바인더의 목차(이름과 설명)만 항상 기억하고, 필요할 때만 해당 장을 펼쳐 읽습니다.

## 6.2 핵심 원리: 점진적 공개(Progressive Disclosure)

```mermaid
flowchart LR
    A["① 메타데이터<br/>name + description<br/>(항상 로드, 수십 토큰)"] -->|관련 작업 감지| B["② SKILL.md 본문<br/>(필요할 때 로드)"]
    B -->|더 자세한 정보 필요| C["③ 참고 파일·스크립트<br/>(요청 시에만 읽거나 실행)"]
```

이 구조 덕분에 수십 개의 Skill을 설치해도 컨텍스트를 거의 차지하지 않습니다. 그래서 **description을 잘 쓰는 것이 Skill 품질의 절반**입니다. Claude는 description만 보고 언제 이 Skill을 써야 할지 판단하기 때문입니다.

## 6.3 Skill vs. Project vs. MCP

|구분|Project|Skill|MCP|
|---|---|---|---|
|한 줄 정의|주제별 작업 공간|재사용 가능한 "방법(How)"|외부 시스템에 대한 "접근(Access)"|
|담는 것|지침 + 배경 자료|절차 + 스크립트 + 템플릿|도구(API) + 데이터 연결|
|적용 범위|해당 프로젝트 대화만|모든 대화에서 자동 호출|연결된 모든 대화|
|예시|"2027 신제품 런칭"|"우리 회사 양식으로 보고서 만들기"|"Notion·Jira·DB에서 데이터 읽기"|

<aside>

**TIP** — 세 가지는 함께 쓸 때 가장 강력합니다. **MCP**로 Jira에서 이슈를 가져오고, **Skill**에 정의된 주간 보고서 양식으로 정리하고, **Project**의 팀 맥락을 반영하는 식입니다.

## 6.4 Skill의 폴더 구조

```
weekly-report/
├── SKILL.md            # (필수) 메타데이터 + 지침
├── reference/
│   ├── style-guide.md  # 필요할 때만 읽는 상세 자료
│   └── examples.md
├── templates/
│   └── report.docx     # 결과물 템플릿
└── scripts/
    └── build_chart.py  # Claude가 실행하는 스크립트
```

## 6.5 [SKILL.md](http://SKILL.md) 작성하기

`SKILL.md` 는 맨 위의 **YAML 프런트매터**와 그 아래 **Markdown 본문**으로 구성됩니다.

```markdown
---
name: weekly-report
description: 팀의 주간 업무 보고서를 회사 표준 양식으로 작성한다. 사용자가 "주간 보고",
  "위클리 리포트", "이번 주 업무 정리"를 요청하거나 업무 목록을 보고서로 만들어
  달라고 할 때 사용한다.
---

# 주간 보고서 작성

## 절차
1. 사용자에게서 이번 주 업무 목록을 받는다. 없으면 연결된 도구(Jira, 캘린더)에서 찾는다.
2. 업무를 "완료 / 진행 중 / 이슈" 세 범주로 분류한다.
3. `reference/style-guide.md` 의 문체 규칙을 따라 작성한다.
4. 수치 데이터가 있으면 `scripts/build_chart.py` 를 실행해 차트를 만든다.
5. `templates/report.docx` 양식에 맞춰 Word 파일로 출력한다.

## 규칙
- 각 항목은 "무엇을 했고 → 결과는 무엇이며 → 다음은 무엇"의 구조로 쓴다.
- 이슈에는 반드시 필요한 지원과 기한을 적는다.

## 예시
자세한 예시는 `reference/examples.md` 를 참고한다.
```

## 6.6 Skill 사용처

[claude.ai](http://claude.ai) / 데스크톱

**Settings → Capabilities → Skills**에서 Anthropic이 제공하는 기본 Skill(Word, Excel, PowerPoint, PDF 등)을 켜거나, 직접 만든 Skill 폴더를 ZIP으로 업로드합니다. 또는 대화에서 "Skill 만들기를 도와줘"라고 하면 _skill-creator_가 인터뷰하듯 함께 만들어 줍니다. 코드 실행 기능이 켜져 있어야 합니다.

Claude Code

개인용은 `~/.claude/skills/<이름>/SKILL.md`, 프로젝트 공용은 `.claude/skills/<이름>/SKILL.md` 에 두면 자동으로 인식됩니다. Git으로 공유하면 팀 전체가 같은 Skill을 씁니다. `/이름` 으로 직접 호출할 수도 있습니다.

Claude API

Skills API로 Skill을 업로드하고, Messages API 요청의 `container` 에 Skill을 지정해 코드 실행 도구와 함께 사용합니다. (Part 3에서 다룹니다.)

조직 배포

Team/Enterprise 관리자는 조직 전체에 Skill을 배포하고, 플러그인 형태로 Skill·커넥터·명령어를 묶어 공유할 수 있습니다.

## 6.7 Skill 설계 모범 사례

- 📏 [SKILL.md](http://SKILL.md)는 간결하게 (500줄 이하 권장)
    
    본문에는 핵심 절차만 두고, 긴 레퍼런스는 별도 파일로 분리해 "필요하면 X를 읽어라"라고 안내하세요. Claude는 이미 똑똑하므로, 일반 상식은 쓰지 말고 **우리 조직만의 규칙과 노하우**에 집중하세요.
    
- 🎯 자유도를 작업에 맞게
    
    창의적 작업은 원칙만 제시하고, 실수가 치명적인 작업(예: DB 마이그레이션)은 정확한 순서와 검증 단계를 명시하거나 스크립트로 고정하세요.
    
- 🧪 실제 사용 테스트
    
    Skill을 만든 뒤 실제 요청 3~5개로 호출되는지, 결과가 기대에 맞는지 확인하세요. 호출이 안 되면 description에 사용자 표현을 추가하고, 잘못 호출되면 범위를 좁히세요.
    
- 🔐 보안
    
    Skill은 코드를 실행할 수 있습니다. **출처를 신뢰할 수 있는 Skill만 설치**하고, 설치 전 [SKILL.md](http://SKILL.md)와 스크립트를 직접 읽어보세요. 외부 서버로 데이터를 보내는 코드가 없는지 특히 주의하세요.
