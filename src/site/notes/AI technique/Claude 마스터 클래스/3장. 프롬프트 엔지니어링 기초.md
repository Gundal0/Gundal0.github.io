## 3.1 프롬프트란 "유능한 신입사원에게 주는 업무 지시서"

> Claude를 **매우 똑똑하지만 우리 회사의 사정을 전혀 모르는 신입사원**이라고 생각하세요. 동료에게 보여주었을 때 "이것만 보고는 뭘 해야 할지 모르겠는데?"라는 반응이 나오는 지시문은 Claude에게도 부족합니다.

## 3.2 좋은 프롬프트의 6요소

|#|요소|질문|예시|
|---|---|---|---|
|1|**목적(Task)**|무엇을 해야 하는가?|신제품 출시 보도자료를 작성해줘|
|2|**맥락(Context)**|왜, 어떤 상황인가?|우리는 B2B SaaS 스타트업이고 주 고객은 중견 제조사야|
|3|**역할(Role)**|누구의 관점으로?|10년 경력의 테크 PR 전문가로서|
|4|**형식(Format)**|어떤 모양으로?|제목 1개, 부제 1개, 본문 4문단, 600자 이내|
|5|**예시(Examples)**|원하는 결과의 샘플은?|아래 작년 보도자료의 문체를 참고해|
|6|**제약(Constraints)**|하지 말아야 할 것은?|경쟁사 이름 언급 금지, 검증되지 않은 수치 사용 금지|

## 3.3 핵심 기법 7가지

### ① 명확하고 구체적으로 쓰기

"짧게" 대신 "3문장으로", "잘" 대신 "중학생도 이해할 수 있게"처럼 **측정 가능한 기준**을 주세요. 그리고 지시의 **이유**를 함께 알려주면 Claude가 예외 상황에서도 올바르게 판단합니다.

<aside>  
❌

말줄임표를 쓰지 마.

</aside>

<aside>  
✅

이 글은 TTS로 읽힐 거야. 음성 엔진이 말줄임표를 발음하지 못하니 쉬표나 마침표로 바꿔줘.

</aside>

### ② XML 태그로 구조화하기

긴 자료와 지시를 섞어 쓸 때는 태그로 구분하면 Claude가 헷갈리지 않습니다. 태그 이름은 자유롭게 정해도 됩니다.

```xml
다음 계약서를 검토해줘.

<contract>
(계약서 전문 붙여넣기)
</contract>

<checklist>
- 손해배상 한도
- 계약 해지 조건
- 지식재산권 귀속
</checklist>

<output_format>
항목별로 "조항 번호 / 현재 내용 / 위험도(상·중·하) / 수정 제안" 표로 작성
</output_format>
```

### ③ 예시 보여주기 (Few-shot)

원하는 결과물의 예시를 2~3개 보여주는 것은 긴 설명보다 강력합니다. 단, Claude는 예시를 매우 충실히 따르므로 **다양한 유형의 예시**를 주어야 한 가지 패턴만 복제하는 것을 막을 수 있습니다.

```xml
고객 리뷰를 긍정/부정/중립으로 분류해줘.

<examples>
<example>
리뷰: 배송이 하루 늦었지만 품질은 최고예요.
분류: 긍정
</example>
<example>
리뷰: 사진과 색이 다르고 환불도 어렵네요.
분류: 부정
</example>
<example>
리뷰: 그냥 가격대비 무난합니다.
분류: 중립
</example>
</examples>

리뷰: {{새 리뷰}}
```

### ④ 생각할 시간 주기 (Chain of Thought)

복잡한 문제는 "단계별로 생각한 뒤 답해줘"라고 요청하거나 **확장 사고**를 켭니다. 최신 모델은 스스로 사고량을 조절하므로, 지나치게 세세한 사고 절차를 강제하기보다는 문제와 판단 기준을 명확히 주는 편이 더 효과적입니다.

### ⑤ 역할 부여하기 (Role Prompting)

"너는 금융 규제 전문 변호사야"처럼 역할을 주면 어휘, 관점, 깊이가 달라집니다. 역할만으로는 부족하므로 맥락·형식과 함께 쓰세요.

### ⑥ 무엇을 하지 말라보다 무엇을 하라고 쓰기

|~~부정형 지시~~|긍정형 지시|
|---|---|
|~~전문 용어를 쓰지 마~~|전문 용어는 처음 나올 때 괄호로 쉽게 풀어서 써줘|
|~~너무 길게 쓰지 마~~|500자 이내로 핵심만 써줘|
|~~목록을 쓰지 마~~|자연스러운 문단형 산문으로 써줘|

### ⑦ 반복하며 다듬기 (Iteration)

첫 답변은 초안입니다. "더 짧게", "두 번째 문단을 숫자 중심으로", "반대 의견을 가진 임원이 읽는다고 가정하고 다시"처럼 구체적인 피드백으로 2~3번 다듬으면 품질이 크게 올라갑니다.

## 3.4 만능 프롬프트 템플릿

<aside>  
📋

아래 템플릿을 복사해서 빈칸만 채워 쓰세요. 항목이 필요 없으면 지워도 됩니다.

</aside>

```markdown
# 역할
너는 [분야]의 [경력/수준] 전문가야.

# 배경
- 나는 [직무/상황]이고, 이 결과물은 [독자]가 [목적]으로 사용할 거야.
- 참고 자료:
<reference>
[자료 붙여넣기]
</reference>

# 해야 할 일
[구체적인 작업을 한두 문장으로]

# 출력 형식
- 구성: [예: 요약 → 본문 → 결론]
- 분량: [예: 1,000자 내외]
- 톤: [예: 존댓말, 간결하고 단정적으로]

# 제약 조건
- [예: 출처가 불확실한 수치는 "확인 필요"로 표시]

# 예시 (선택)
<example>
[원하는 결과물 샘플]
</example>
```

## 3.5 환각을 줄이는 방법

1. **모르면 모른다고 말해도 된다**고 명시적으로 허용하세요.
2. 문서 기반 질문은 "답변하기 전에 근거가 되는 문장을 먼저 인용해줘"라고 요청하세요.
3. 최신 정보가 필요하면 **웹 검색**을 켜고 출처 링크를 요구하세요.
4. 중요한 사실은 항상 원문을 직접 확인하세요.

## 3.6 실전 프롬프트 예시집

- 📧 이메일 답장 작성
    
    ```
    아래는 거래처에서 받은 납기 지연 항의 메일이야. 우리는 관계를 유지하고 싶지만
    다음 주까지 납품은 꼭 필요해. 정중하지만 단호한 톤으로, 대안 일정 2가지를 제안하는
    답장을 300자 내외로 써줘.
    
    <email>
    (원문)
    </email>
    ```
    
- 📊 데이터 분석 요청
    
    ```
    첨부한 CSV는 지난 12개월 지역별 매출이야. 경영진 보고용으로
    1) 전체 추세 한 문장 2) 성장률 상위·하위 3개 지역 3) 이상치와 그 원인 가설
    2) 다음 분기 액션 제안 3가지를 정리하고, 추세를 보여주는 차트를 만들어줘.
    계산은 반드시 코드로 수행해줘.
    ```
    
- 🎓 개념 학습
    
    ```
    나는 비전공자인데 "벡터 데이터베이스"를 이해하고 싶어.
    1) 일상적인 비유로 먼저 설명하고 2) 정확한 정의를 알려준 뒤
    2) 내가 이해했는지 확인하는 퀴즈 3개를 내줘. 퀴즈 정답은 내가 답한 뒤에 알려줘.
    ```
