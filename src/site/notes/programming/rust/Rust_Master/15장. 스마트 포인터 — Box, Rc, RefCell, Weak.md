> 📖 **스토리** — 조직도 트리를 만들다가 하린은 세 번 벽에 부딪혔다. 재귀 타입의 크기를 모른다고 하고, 한 팀원을 두 팀이 공유할 수 없다고 하고, 부모를 가리키면 메모리가 새었다.

## 🧩 문제 1 — E0072: recursive type has infinite size

```rust
enum List { Cons(i32, List), Nil }  // ❌ List 안에 List가 통째로 들어가 크기가 무한
```

## 💡 해결 1 — `Box<T>`: 힙에 두고 포인터만 들고 다니기

```rust
#[derive(Debug)]
enum List { Cons(i32, Box<List>), Nil }   // Box는 포인터 크기(8바이트)로 고정

use List::{Cons, Nil};

fn sum(list: &List) -> i32 {
    match list {
        Cons(v, rest) => v + sum(rest),
        Nil => 0,
    }
}

fn main() {
    let list = Cons(1, Box::new(Cons(2, Box::new(Cons(3, Box::new(Nil))))));
    println!("{}", sum(&list)); // 6

    let big = Box::new([0u8; 1_000_000]); // 큰 데이터를 스택 대신 힙에
    println!("{}", big.len());
}
```

## 🧩 문제 2 — 하나의 값을 여러 소유자가 공유해야 한다

## 💡 해결 2 — `Rc<T>`: 참조 카운팅

```rust
use std::rc::Rc;

#[derive(Debug)]
struct Member { name: String }

fn main() {
    let harin = Rc::new(Member { name: "하린".into() });
    let backend_team = vec![Rc::clone(&harin)];   // 포인터만 복제, 카운트 +1
    let rust_guild = vec![Rc::clone(&harin)];
    println!("참조 수 = {}", Rc::strong_count(&harin)); // 3
    drop(backend_team);
    println!("참조 수 = {}", Rc::strong_count(&harin)); // 2
    println!("{}", rust_guild[0].name);
}
```

## 🧩 문제 3 — 공유된 값을 수정하고 싶다

`Rc<T>` 는 불변 참조만 줍니다. 하지만 하린의 직함을 바꿔야 한다.

## 💡 해결 3 — `RefCell<T>`: 런타임 빌림 검사(내부 가변성)

```rust
use std::cell::RefCell;
use std::rc::Rc;

#[derive(Debug)]
struct Member { name: String, title: String }

fn main() {
    let harin = Rc::new(RefCell::new(Member { name: "하린".into(), title: "주니어".into() }));
    let team = vec![Rc::clone(&harin)];

    harin.borrow_mut().title = "미들".into();      // 가변 빌림 (런타임 검사)
    println!("{}: {}", team[0].borrow().name, team[0].borrow().title); // 하린: 미들

    // ⚠️ 규칙 위반은 컴파일이 아니라 실행 중 panic
    // let a = harin.borrow_mut();
    // let b = harin.borrow_mut(); // panic: already mutably borrowed
    if let Ok(mut m) = harin.try_borrow_mut() { m.title.push('!'); } // panic 없는 버전
}
```

## 🧩 문제 4 — 부모↔자식 상호 참조로 메모리가 새었다

`Rc` 로 서로를 가리키면 참조 수가 0이 되지 않아 영원히 해제되지 않습니다(순환 참조).

## 💡 해결 4 — `Weak<T>`: 소유하지 않는 참조

```rust
use std::cell::RefCell;
use std::rc::{Rc, Weak};

#[derive(Debug)]
struct Node {
    name: String,
    parent: RefCell<Weak<Node>>,          // 부모는 약한 참조
    children: RefCell<Vec<Rc<Node>>>,     // 자식은 강한 참조
}

fn node(name: &str) -> Rc<Node> {
    Rc::new(Node { name: name.into(), parent: RefCell::new(Weak::new()), children: RefCell::new(vec![]) })
}

fn main() {
    let cto = node("CTO");
    let harin = node("하린");
    *harin.parent.borrow_mut() = Rc::downgrade(&cto);
    cto.children.borrow_mut().push(Rc::clone(&harin));

    let boss = harin.parent.borrow().upgrade();   // Option<Rc<Node>>: 살아 있으면 Some
    println!("{}의 상사: {:?}", harin.name, boss.map(|b| b.name.clone()));
    println!("strong={} weak={}", Rc::strong_count(&cto), Rc::weak_count(&cto)); // 1, 1
}
```

## 🔍 원리 — 스마트 포인터 선택 가이드

|타입|소유자|가변성|스레드|용도|
|---|---|---|---|---|
|`Box<T>`|1|컴파일 검사|T에 따름|재귀 타입, 큰 데이터, `dyn Trait`|
|`Rc<T>`|여러|불변|❌|단일 스레드 공유|
|`Arc<T>`|여러|불변|✅|멀티스레드 공유 (17장)|
|`Cell<T>`|1|값 교체|❌|Copy 타입의 내부 가변성|
|`RefCell<T>`|1|런타임 검사|❌|내부 가변성|
|`Mutex<T>` / `RwLock<T>`|1|락|✅|스레드 간 내부 가변성|
|`Cow<'a, T>`|빌림 또는 소유|쓸 때 복사|T에 따름|대부분 읽기만 하고 가끔 수정|

### Deref 트레이트 — 스마트 포인터가 참조처럼 동작하는 이유

```rust
use std::ops::Deref;

struct MyBox<T>(T);

impl<T> Deref for MyBox<T> {
    type Target = T;
    fn deref(&self) -> &T { &self.0 }
}

fn hello(name: &str) { println!("안녕, {name}"); }

fn main() {
    let b = MyBox(String::from("하린"));
    hello(&b);   // &MyBox<String> → &String → &str (역참조 강제 변환, deref coercion)
}
```
