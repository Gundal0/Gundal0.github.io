## 🧩 문제 — CPU를 많이 쓰는 대량 데이터 처리가 느리다

## 💡 해결 — 병렬 이터레이터

```rust
use rayon::prelude::*;
use std::time::Instant;

fn is_prime(n: u64) -> bool {
    n >= 2 && (2..).take_while(|d| d * d <= n).all(|d| n % d != 0)
}

fn main() {
    let range = 1..5_000_000u64;

    let t = Instant::now();
    let seq = range.clone().filter(|&n| is_prime(n)).count();
    println!("순차: {seq}개, {:?}", t.elapsed());

    let t = Instant::now();
    let par = range.into_par_iter().filter(|&n| is_prime(n)).count();   // 바뀐 건 이 한 줄
    println!("병렬: {par}개, {:?}", t.elapsed());

    // 병렬 정렬, 병렬 map/reduce
    let mut data: Vec<u32> = (0..1_000_000).rev().collect();
    data.par_sort_unstable();
    let sum_sq: u64 = data.par_iter().map(|&x| (x as u64) * (x as u64)).sum();

    // 두 작업을 동시에 (분할 정복)
    let (a, b) = rayon::join(|| data[..500_000].iter().max(), || data[500_000..].iter().min());
    println!("{sum_sq} {a:?} {b:?}");
}
```

<aside>  
🔍

rayon은 **작업 훔치기(work stealing)** 스레드 풀로 작업을 고르게 나눕니다. 클로저는 `Send`/`Sync` 제약을 따르므로 데이터 경쟁이 있는 코드는 컴파일되지 않습니다. 단, I/O 대기 작업에는 rayon이 아니라 tokio(async)가 맞습니다.

</aside>
