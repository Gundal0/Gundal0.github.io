> 📖 **스토리** — 설정 파일을 읽는 코드가 고객 환경에서 `unwrap()` panic으로 죽었다. 페리스: "실패는 예외가 아니라 **값**이야. 함수가 실패할 수 있다면 타입에 그렇게 적어."

## 🔍 원리 — 두 종류의 에러

<aside>  
💥

**복구 불가능 → `panic!`**

버그, 불변식 위반. 프로그램(스레드)을 중단한다.

예) 배열 범위 초과, `unreachable!()`

</aside>

<aside>  
🛠️

**복구 가능 → `Result<T, E>`**

파일 없음, 네트워크 실패, 잘못된 입력. 호출자가 결정한다.

`enum Result<T, E> { Ok(T), Err(E) }`

</aside>

## 🧩 문제 1 — match가 너무 깊어진다

```rust
use std::fs;

fn read_port() -> Result<u16, String> {
    match fs::read_to_string("port.txt") {
        Ok(text) => match text.trim().parse::<u16>() {
            Ok(port) => Ok(port),
            Err(e) => Err(format!("숫자 아님: {e}")),
        },
        Err(e) => Err(format!("파일 오류: {e}")),
    }
}
```

## 💡 해결 1 — `?` 연산자

`?` 는 `Ok` 면 값을 꺼내고, `Err` 면 즉시 함수에서 반환합니다(에러 타입은 `From` 으로 자동 변환). `Option` 을 반환하는 함수에서는 `Option` 에도 쓸 수 있습니다.

```rust
use std::fs;

fn read_port() -> Result<u16, Box<dyn std::error::Error>> {
    let text = fs::read_to_string("port.txt")?;  // io::Error → Box<dyn Error>
    let port = text.trim().parse::<u16>()?;      // ParseIntError → Box<dyn Error>
    Ok(port)
}

fn main() {
    match read_port() {
        Ok(p) => println!("포트 {p}"),
        Err(e) => eprintln!("설정 읽기 실패: {e} → 기본값 8080 사용"),
    }
}
```

<aside>  
💡

`main` 도 `Result` 를 반환할 수 있습니다: `fn main() -> Result<(), Box<dyn std::error::Error>> { ...; Ok(()) }`. 에러가 나면 메시지를 출력하고 종료 코드 1로 끝납니다.

</aside>

## 🧩 문제 2 — 호출자가 에러 종류에 따라 다르게 대응하고 싶다

`Box<dyn Error>` 는 편하지만 "파일이 없어서"인지 "형식이 틀려서"인지 타입으로 구분할 수 없습니다.

## 💡 해결 2 — 직접 만든 에러 타입

```rust
use std::{fmt, fs, io, num::ParseIntError};

#[derive(Debug)]
enum ConfigError {
    Io(io::Error),
    Parse(ParseIntError),
    OutOfRange(u16),
}

impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            ConfigError::Io(e) => write!(f, "파일을 읽을 수 없습니다: {e}"),
            ConfigError::Parse(e) => write!(f, "포트 형식이 잘못되었습니다: {e}"),
            ConfigError::OutOfRange(p) => write!(f, "{p}번 포트는 사용할 수 없습니다 (1024 이상)"),
        }
    }
}

impl std::error::Error for ConfigError {}

// From 구현 덕분에 ? 가 자동 변환해 줌
impl From<io::Error> for ConfigError {
    fn from(e: io::Error) -> Self { ConfigError::Io(e) }
}
impl From<ParseIntError> for ConfigError {
    fn from(e: ParseIntError) -> Self { ConfigError::Parse(e) }
}

fn read_port(path: &str) -> Result<u16, ConfigError> {
    let port: u16 = fs::read_to_string(path)?.trim().parse()?;
    if port < 1024 {
        return Err(ConfigError::OutOfRange(port));
    }
    Ok(port)
}

fn main() {
    match read_port("port.txt") {
        Ok(p) => println!("포트 {p}"),
        Err(ConfigError::Io(e)) if e.kind() == io::ErrorKind::NotFound => {
            println!("설정 파일이 없어 기본값 8080을 사용합니다");
        }
        Err(e) => eprintln!("오류: {e}"),
    }
}
```

<aside>  
📦

실무에서는 이 보일러플레이트를 **thiserror**(라이브러리용)와 **anyhow**(애플리케이션용) 크레이트로 줄입니다. → 라이브러리 강좌 _anyhow & thiserror_ 편 참고

</aside>

## 🔍 Result/Option 콤비네이터 치트시트

|메서드|동작|
|---|---|
|`map(f)`|Ok/Some 안의 값을 변환|
|`map_err(f)`|Err 안의 에러를 변환|
|`and_then(f)`|실패할 수 있는 다음 단계를 연결|
|`unwrap_or(v)` / `unwrap_or_else(f)` / `unwrap_or_default()`|실패 시 기본값|
|`ok()` / `ok_or(e)`|Result→Option / Option→Result|
|`is_ok()` / `is_some()`|성공 여부만 확인|
|`?`|실패를 호출자에게 전파|

## 🏋️ 연습 문제

- Q1. `"3,5,x,7"` 같은 문자열을 받아 모든 숫자를 파싱하되, 하나라도 실패하면 에러를 반환하는 함수를 작성하세요.
    
    ```rust
    fn parse_all(s: &str) -> Result<Vec<i32>, std::num::ParseIntError> {
        s.split(',').map(|p| p.trim().parse::<i32>()).collect()
    }
    ```
    
    `Iterator<Item = Result<T, E>>` 는 `Result<Vec<T>, E>` 로 `collect` 할 수 있습니다. 최초의 에러에서 멈춥니다.
