> 📖 **스토리** — 두 문자열 중 더 긴 것을 돌려주는 간단한 함수였다. 그런데 컴파일러가 `missing lifetime specifier` 를 외쳤다. 하린: "제가 무엇을 더 알려줘야 하죠?"

## 🧩 문제 1 — E0106: missing lifetime specifier

```rust
fn longest(a: &str, b: &str) -> &str {   // ❌ 반환값이 a의 참조인지 b의 참조인지 모름
    if a.len() > b.len() { a } else { b }
}
```

## 💡 해결 1 — 라이프타임 매개변수

```rust
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() > b.len() { a } else { b }
}

fn main() {
    let outer = String::from("긴 문자열입니다");
    let result;
    {
        let inner = String::from("짧음");
        result = longest(outer.as_str(), inner.as_str());
        println!("{result}");    // ✅ inner가 살아 있는 동안 사용
    }
    // println!("{result}");     // ❌ inner가 이미 해제됐을 수 있음
}
```

<aside>  
🔍

`'a` 는 수명을 **늘려주는 것이 아니라** 관계를 **설명**하는 것입니다. "반환되는 참조는 a와 b 중 더 짧게 사는 쪽만큼만 유효하다"는 계약을 컴파일러에게 알려주면, 호출하는 쪽의 사용을 검사할 수 있게 됩니다.

</aside>

## 🧩 문제 2 — 구조체에 참조를 저장하고 싶다

큰 로그 파일을 복사하지 않고 토큰 단위로 나누는 파서를 만들고 싶다.

## 💡 해결 2 — 라이프타임을 가진 구조체

```rust
#[derive(Debug)]
struct LogLine<'a> {
    level: &'a str,
    message: &'a str,
}

struct Parser<'a> {
    lines: std::str::Lines<'a>,
}

impl<'a> Parser<'a> {
    fn new(text: &'a str) -> Self { Parser { lines: text.lines() } }
}

impl<'a> Iterator for Parser<'a> {
    type Item = LogLine<'a>;
    fn next(&mut self) -> Option<Self::Item> {
        let line = self.lines.next()?;
        let (level, message) = line.split_once(' ')?;
        Some(LogLine { level, message })     // 원본 text를 가리키는 슬라이스 (복사 없음)
    }
}

fn main() {
    let log = String::from("INFO 서버 시작\nWARN 디스크 80%\nERROR DB 연결 실패");
    let errors: Vec<LogLine> = Parser::new(&log).filter(|l| l.level == "ERROR").collect();
    println!("{errors:?}");
}
```

## 🔍 원리 — 라이프타임 생략 규칙

대부분의 경우 라이프타임을 안 써도 되는 이유는 컴파일러가 아래 규칙으로 추론하기 때문입니다.

1. 각 참조 매개변수는 각자 다른 라이프타임을 받는다.
2. 입력 라이프타임이 **딱 하나**면 모든 출력에 그것을 쓴다. (`fn first(s: &str) -> &str`)
3. 메서드에 `&self` / `&mut self` 가 있으면 출력에 self의 라이프타임을 쓴다.

이 규칙으로 결정되지 않을 때만(위의 `longest`) 직접 적습니다.

## 🔍 더 알아두기

```rust
// 'static: 프로그램 전체 기간 유효 (문자열 리터럴, static 변수)
let s: &'static str = "바이너리에 박혀 있음";

// T: 'static 경계 = T가 빌린 참조를 포함하지 않거나 'static 참조만 포함 (thread::spawn에서 자주 봄)
fn spawn_job<T: Send + 'static>(t: T) {}

// 여러 라이프타임과 관계
fn pick_first<'a, 'b>(a: &'a str, _b: &'b str) -> &'a str { a }   // b와 무관
fn outlive<'long: 'short, 'short>(x: &'long str) -> &'short str { x } // 'long이 'short보다 오래 살아야 함

// 익명 라이프타임 '_ : "추론해줘"
impl std::fmt::Display for LogLine<'_> {
    fn fmt(&self, f: &mut std::fmt::Formatter<'_>) -> std::fmt::Result {
        write!(f, "[{}] {}", self.level, self.message)
    }
}
```

<aside>  
⚠️

**함정** — 라이프타임 오류가 복잡해지면, 참조 대신 **소유 타입(`String`, `Vec`)**을 저장하는 것이 대개 더 좋은 설계입니다. 라이프타임은 성능이 중요한 곳에서 써도 늦지 않습니다.

</aside>
