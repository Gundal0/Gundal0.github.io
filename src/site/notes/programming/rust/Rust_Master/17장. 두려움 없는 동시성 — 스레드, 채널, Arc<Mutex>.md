> 📖 **스토리** — 이미지 1만 장의 썸네일을 만드는 데 10분이 걸린다. CPU는 8코어인데 하나만 일하고 있었다. 페리스: "다른 언어에서 멀티스레드는 도박이지만, Rust에서는 데이터 경쟁이 **컴파일 오류**야."

## 🧩 문제 1 — E0373: closure may outlive the current function

```rust
use std::thread;

fn main() {
    let files = vec!["a.png", "b.png"];
    let handle = thread::spawn(|| {
        println!("{files:?}");   // ❌ 스레드가 main보다 오래 살 수 있는데 files를 빌려 쓰려 함
    });
    handle.join().unwrap();
}
```

## 💡 해결 1 — `move` 또는 스코프 스레드

```rust
use std::thread;

fn main() {
    // A) move: 소유권을 스레드로 넘김
    let files = vec!["a.png", "b.png"];
    let handle = thread::spawn(move || files.len());
    println!("처리 개수: {}", handle.join().unwrap()); // join은 스레드의 반환값을 돌려줌

    // B) thread::scope: 스코프가 끝나기 전에 모든 스레드가 join됨을 보장 → 빌림 가능
    let images: Vec<u32> = (1..=8).collect();
    let mut results = vec![0; images.len()];
    thread::scope(|s| {
        for (img, out) in images.iter().zip(results.iter_mut()) {
            s.spawn(move || {
                *out = img * 100;            // 각 스레드가 서로 다른 칸을 수정
            });
        }
    });
    println!("{results:?}");
}
```

## 🧩 문제 2 — 작업 스레드들의 결과를 한 곳으로 모으고 싶다

## 💡 해결 2 — 메시지 전달: 채널(mpsc)

```rust
use std::sync::mpsc;
use std::thread;
use std::time::Duration;

fn main() {
    let (tx, rx) = mpsc::channel::<(usize, String)>();

    for worker in 0..3 {
        let tx = tx.clone();                       // 송신자는 여러 개(multi-producer)
        thread::spawn(move || {
            for job in 0..2 {
                thread::sleep(Duration::from_millis(50));
                tx.send((worker, format!("job-{job} 완료"))).unwrap();
            }
        });
    }
    drop(tx);                                      // 원본 송신자를 닫아야 수신 루프가 끝남

    for (worker, msg) in rx {                      // 모든 송신자가 닫히면 종료
        println!("worker {worker}: {msg}");
    }
}
```

## 🧩 문제 3 — 여러 스레드가 하나의 카운터를 올려야 한다

## 💡 해결 3 — 공유 상태: `Arc<Mutex<T>>`

```rust
use std::collections::HashMap;
use std::sync::{Arc, Mutex, RwLock};
use std::sync::atomic::{AtomicUsize, Ordering};
use std::thread;

fn main() {
    let processed = Arc::new(Mutex::new(Vec::new()));    // Arc = 스레드 안전 Rc
    let counter = Arc::new(AtomicUsize::new(0));         // 단순 카운터는 원자적 타입이 더 빠름
    let config = Arc::new(RwLock::new(HashMap::from([("quality", 80)])));

    let handles: Vec<_> = (0..4)
        .map(|id| {
            let processed = Arc::clone(&processed);
            let counter = Arc::clone(&counter);
            let config = Arc::clone(&config);
            thread::spawn(move || {
                let q = config.read().unwrap()["quality"];  // 읽기 락은 여러 개 동시 가능
                counter.fetch_add(1, Ordering::Relaxed);
                let mut list = processed.lock().unwrap();   // 락 획득 (MutexGuard)
                list.push(format!("thread-{id} q={q}"));
            }) // ← guard가 drop되며 자동 언락
        })
        .collect();

    for h in handles { h.join().unwrap(); }
    config.write().unwrap().insert("quality", 90);       // 쓰기 락은 단독
    println!("{} / {:?}", counter.load(Ordering::Relaxed), processed.lock().unwrap());
}
```

<aside>  
⚠️

**함정 — 데드락**: Rust는 데이터 경쟁은 막지만 데드락은 막지 못합니다. 락을 잡은 채로 오래 작업하지 말고, 여러 락은 항상 **같은 순서**로 잡으세요. 가드를 빨리 놓으려면 블록 `{ }` 으로 감싸거나 `drop(guard)` 하세요.

</aside>

## 🔍 원리 — Send와 Sync

<aside>  
📤

**`Send`**

값의 **소유권을 다른 스레드로 옮길 수 있음**. 대부분의 타입이 Send. `Rc<T>` 는 아님.

</aside>

<aside>  
🔗

**`Sync`**

**`&T` 를 여러 스레드가 동시에 가져도 안전**. `RefCell<T>`, `Cell<T>` 는 아님.

</aside>

두 트레이트는 구성 요소가 모두 Send/Sync면 컴파일러가 **자동으로** 구현합니다. `thread::spawn` 은 클로저에 `Send + 'static` 을 요구하므로, `Rc` 를 스레드로 넘기려 하면 컴파일 오류가 나며 버그가 원천 차단됩니다.

📦

</aside>
